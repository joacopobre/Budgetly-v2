# Budgetly redesign

Phase 1 was the landing page. Phase 2 was the inside of the app. Both are done.

## Where things live

| What | Where |
| --- | --- |
| Design tokens (colour, type, radii, shadows, motion) | `styles/tokens.css` |
| Tailwind utilities mapped from the tokens | `app/globals.css` (`@theme inline`, "Budgetly design tokens") |
| Motion values for GSAP | `lib/motion.ts` |
| Shared component classes (buttons, cards, forms, tables, modals) | `styles/ui.css` |
| Currency formatting | `lib/currency.ts` |
| Landing page | `app/(marketing)/` and `components/landing/` |
| Product demo sources (HyperFrames) | `demos/` |
| Product demos as served to the browser | `public/demos/` (generated by `npm run demos:sync`) |

The demos and the app share one look: same tokens, same components, same
motion. Change a token and both follow.

## Landing page

- `app/(marketing)/page.tsx` composes the sections in `components/landing/`.
- Scroll animation is GSAP + ScrollTrigger (`lib/gsap.ts`). Nothing is pinned
  or scroll-jacked: the hero background and the demo stage use CSS
  `position: sticky`, and ScrollTrigger only reads scroll progress.
- The hero line-work is one WebGL fragment shader
  (`components/landing/GuillocheCanvas.tsx`), with no 3D library.
- Everything animated checks `prefers-reduced-motion`. With it on, the page
  shows the finished state of each section and still frames of the demos.

## Product demos

Five looping demos, built with HyperFrames, each showing a real feature:
dashboard range switch, add a transaction, import a CSV, fund a budget, set a
spending limit.

- Source: `demos/` is one HyperFrames project. `demos/index.html` is the root
  timeline; each demo is a scene in `demos/compositions/`. Shared UI styles
  and timeline helpers (cursor, typing, counting, camera) are in
  `demos/assets/kit.css` and `demos/assets/kit.js`. The kit reads the same
  `styles/tokens.css` as the app (linked as `demos/assets/tokens.css`).
- Currency in demos is set once, in `Kit.CURRENCY` (`demos/assets/kit.js`).
- Delivery: embedded live with `@hyperframes/player`
  (`components/landing/DemoPlayer.tsx`), not as video. The player and its
  runtime load only when a demo nears the viewport, play only while visible,
  and are self-hosted (`public/demos/vendor/`), so the page makes no
  third-party requests. One player serves all four feature chapters by moving
  between scenes.

Workflow after editing a demo:

```bash
npm run demos:preview   # HyperFrames Studio, to edit and scrub
npm run demos:check     # lint + runtime + layout checks
npm run demos:sync      # copy to public/demos and refresh lib/demos.manifest.json
npm run demos:posters   # re-render the still frames (needs ffmpeg)
```

`demos:check` reports text-overlap findings where menus and modals cover the
page behind them, and film-oriented advice (minimum type size, no soundtrack).
Those are expected for UI demos.

The vendored runtime in `public/demos/vendor/` must match the
`@hyperframes/player` version in `package.json` (0.9.40).

## Phase 2: the app

Done. Every page outside the landing (login, signup, forgot and reset
password, dashboard, transactions, budgets, settings) and the shared pieces
(nav, modals, date picker, CSV import, onboarding tour, charts) use the tokens.
Presentation only: no logic, API, auth or database changes.

- Shared component classes live in `styles/ui.css` (`bl-btn`, `bl-card`,
  `bl-input`, `bl-table`, `bl-modal`, `bl-menu`, `bl-chip`, `bl-bar` and so
  on). They sit in `@layer components`, so a Tailwind utility on the same
  element always wins. The landing page uses the same classes.
- The shadcn variables in `app/globals.css` point at the `--bl-*` tokens, so
  `components/ui/*` follows the theme without its own palette.
- Theme: one `ThemeProvider` at the root (`app/providers.tsx`) toggles `dark`
  on `<html>`. An inline script in `app/layout.tsx` sets it before first paint.
  The storage key is in `lib/theme.ts`.
- Fonts: Switzer and Geist Mono only, set once on `<html>` (`app/fonts.ts`).
- Auth pages share `components/auth/AuthShell.tsx`; the side panel
  (`AuthArt.tsx`) reuses the landing page's `GuillocheCanvas`.
- Charts read `var(--bl-accent)` and `var(--bl-fg-faint)` and share
  `components/ui/MoneyTooltip.tsx`.
- Currency: every amount goes through `formatCurrency` in `lib/currency.ts`
  (`lib/transactions/formatMoney.ts` is a thin wrapper). Input prefixes read
  `DEFAULT_CURRENCY.symbol`. Amounts stay plain numbers.

A currency picker can be added as its own feature: read the user's choice,
pass it as `options.currency`, and nothing else changes. `CURRENCIES` in
`lib/currency.ts` already lists GBP, USD and EUR.

If `next dev` keeps serving old styles after an edit to `styles/ui.css`,
delete `.next` and restart it.
